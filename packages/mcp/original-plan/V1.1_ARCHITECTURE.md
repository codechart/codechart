## Example App Structure

Simple todo app with auth - for testing diagram generation.

```
example-app/
├── auth/
│   ├── login.ts      # validate creds → check db → return token
│   ├── register.ts   # validate → check exists → hash → save
│   └── logout.ts     # invalidate token
├── todos/
│   ├── create.ts     # auth check → validate → save
│   ├── list.ts       # auth check → fetch → return
│   └── complete.ts   # auth check → update status
└── README.md
```

**Note**: Code doesn't need to run. Just needs clear logic flow for diagram testing.

## Expected Diagrams

| Question | Expected Nodes |
|----------|----------------|
| "How does login work?" | input creds → validate → check db → success/fail → return token |
| "Show registration flow" | input data → validate → check exists → hash password → save → confirm |
| "How do I create a todo?" | check auth → validate input → save to db → return todo |

## WebSocket Protocol

### MCP → UI
- `render_diagram` - display new diagram
- `request_diagram_json` - get current state
- `request_screenshot` - get image
- `request_selected_nodes` - get selection

### UI → MCP
- `diagram_json_response`
- `screenshot_response`
- `selection_response`
- `selection_changed` (push)

## Tools

- validate_json, send_to_ui, add_to_diagram
- get_diagram_json, get_diagram_image, save_image
- get_selected_nodes, save_diagram, load_diagram
