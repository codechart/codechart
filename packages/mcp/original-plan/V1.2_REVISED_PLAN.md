# Revised Plan — cochart-mcp v1.2

This revision incorporates feedback from the review session. It replaces the original V1.1 plan.

## Key Changes from V1.1

1. **Use existing `LlmJsonItem` interface** — no new schema. MCP server gets a copy + automated verification script to prevent drift.
2. **Reuse existing validation logic** from `.claude/commands/scripts/llm-validate-covalent.js` and `parseLlmJson()` in the UI.
3. **Export/import use identical schema** — fix `mapForLlmJson()` to align with `parseLlmJson()` (code nodes must NOT have `type`, export x/y but don't import them).
4. **Separate MCP communication files in UI** — new Angular service for WebSocket client, not mixed into `llmJson.actions.ts`.
5. **MCP server is standalone** (`packages/mcp/`) — works with Claude Code, Copilot, and other MCP-compatible clients.
6. **MCP talks directly to UI** via WebSocket — not through the API.
7. **Remove `save_diagram` / `load_diagram` tools** — not relevant for MCP use case.
8. **Bug fix**: `mapForLlmJson()` filter is inverted on line 217 — keeps excluded nodes instead of included ones.

## Architecture

```
LLM Client (Claude Code / Copilot / etc.)
        ↓ MCP protocol (stdio)
   MCP Server (standalone Node process)
        ↓ WebSocket
   UI (localhost:4300) ←→ API (localhost:2900)
```

- MCP Server listens on WebSocket port (default 8765)
- UI connects to MCP Server on page load
- UI has dedicated `McpWebSocketService` (new file, separate from existing code)

### Schema

The canonical schema is `LlmJsonItem` in `packages/ui/src/app/search/llmJson.actions.ts`, documented as JSON Schema in `.claude/commands/cochart/write-cochart.md`.

The MCP server gets a **copied version** of the interface. A verification script runs during MCP build to compare the two and fail if they've drifted.

**Export additions**: `mapForLlmJson()` will also emit `x` and `y` (node positions from vis.js).

**Import behavior**: `parseLlmJson()` ignores `x` and `y` — positions are determined by the UI layout engine.

**Type field rules** (aligned with write-cochart.md JSON Schema):
- Code nodes: `type` is **absent** (not undefined, not null — the key must not exist)
- Todo nodes: `type: "todo"`
- Section/remark nodes: `type: "section"` / `type: "remark"` (accepted, passed through)

## Tools

| Tool | Purpose | Reuses |
|------|---------|--------|
| `validate_json` | Validate diagram JSON against LlmJsonItem schema | `llm-validate-covalent.js` logic |
| `send_to_ui` | Push full diagram to UI (replaces current) | `parseLlmJson()` + `processAllItems()` |
| `add_to_diagram` | Merge nodes/edges into existing diagram | `processAllItems()` |
| `get_diagram_json` | Get current diagram state from UI | `mapForLlmJson()` (with x,y) |
| `get_diagram_image` | Get screenshot as base64 | New — UI captures canvas |
| `save_image` | Save screenshot to file | New — MCP writes file |
| `get_selected_nodes` | Get user-selected nodes | New — UI reports selection |

Removed from V1.1: `save_diagram`, `load_diagram` (not relevant).

## WebSocket Protocol

### MCP Server → UI
```typescript
{ type: "render_diagram", payload: LlmJsonItem[] }
{ type: "add_to_diagram", payload: LlmJsonItem[] }
{ type: "request_diagram_json", requestId: string }
{ type: "request_screenshot", requestId: string, maxSize?: number }
{ type: "request_selected_nodes", requestId: string }
```

### UI → MCP Server
```typescript
{ type: "diagram_json_response", requestId: string, data: LlmJsonItem[] }
{ type: "screenshot_response", requestId: string, base64: string, mimeType: string }
{ type: "selection_response", requestId: string, selectedNodes: LlmJsonItem[] }
{ type: "selection_changed", selectedNodes: LlmJsonItem[] }  // push, no requestId needed
```
